# Practice 2 – Predicting Product Sales

## 1. Overview
This project builds a machine-learning pipeline to predict daily product-family sales for retail stores using the Corporación Favorita Store Sales dataset.

**Target:** `sales` (numeric).  
**Prediction grain:** date × store × product family.

## 2. Dataset
Download the competition files from [Kaggle – Store Sales: Time Series Forecasting](https://www.kaggle.com/competitions/store-sales-time-series-forecasting/data) and place them in `data/raw/`:
- `train.csv` (required; includes sales target)
- `stores.csv`
- `holidays_events.csv`
- `oil.csv`
- `transactions.csv` (optional; historical information only)

The supplied holidays file belongs to this dataset and should be named `holidays_events.csv`.

**Dataset limitation:** the assignment description mentions customer demographics, reviews, ratings, customer lifetime value and advertising spend. These fields are not present in the supplied Favorita dataset. This project does not invent them. It uses the actual available fields: date, store, product family, promotion count, store metadata, oil price and holiday/event information.

## 3. Environment
Python 3.10+ is recommended.

```bash
python -m venv .venv
source .venv/bin/activate        # macOS/Linux
# .venv\\Scripts\\activate     # Windows
pip install -r requirements.txt
```

## 4. Run
From this directory:

```bash
python -m scripts.run_pipeline --data-dir data/raw --output-dir outputs
```

The script performs data loading, feature engineering, chronological validation, model training (Linear Regression, Decision Tree, Random Forest), evaluation (MAE, MSE, RMSE), and model persistence.

## 5. Output
- `outputs/metrics/model_comparison.csv`
- `outputs/metrics/best_model.json`
- `outputs/predictions/validation_predictions.csv`
- `models/saved_models/best_model.joblib`

Metrics are generated by running the pipeline; no performance values are pre-filled or fabricated.

## 6. Important methodology notes
- Validation uses a chronological holdout rather than a random split.
- The latest portion of the training timeline is used as validation.
- Promotion and calendar features are derived from available records.
- Lag/rolling sales features are intentionally not used in the baseline validation pipeline because they require careful recursive forecasting and can leak future information if constructed incorrectly.
- Transactions are excluded from the baseline feature set because future transaction totals may not be known at prediction time.
- This is a reproducible local training/demo pipeline, not a deployed production service.
